# Search Quality & Evidence Validation (v1.2)

## 목적

검색 결과의 개수가 아니라 질문에 필요한 근거 유형과 충분성을 평가합니다. 이 단계는 출처 메타데이터 기반의 결정론적 검증이며, 페이지 본문을 읽고 개별 주장을 의미적으로 입증하는 기능은 아닙니다.

## 변경 사항

### 1. 출처 유형 분류

- `official`: 정부·기술 표준·핵심 기술 프로젝트의 1차 출처와 공식 문서 도메인
- `company_official`: 기업의 공식 도메인
- `academic`: 학술 출처
- `news`: 언론사
- `technical_community`: GitHub, Stack Overflow 등 기술 커뮤니티
- `other`: 위 유형에 해당하지 않는 출처

도메인 목록 기반 분류는 휴리스틱입니다. 공식 도메인이라는 사실만으로 특정 페이지의 최신성·정확성·주장 뒷받침 여부가 보장되지는 않습니다.

### 2. 질문별 근거 요건

- 최신 버전·안정 버전·공식 배포 질문: 공식 출처를 요구합니다.
- 기업 도입·고객 활용 사례 질문: 기업 공식 사이트의 자료를 요구합니다.
- 최신성 질문: 게시일 또는 1차 출처의 존재 여부를 확인합니다.
- 과거·역사 질문: 현재 시점의 최신성 요건을 강제로 적용하지 않습니다.

### 3. 버전 충돌 처리

- 제목과 검색 요약에서 버전 표기를 추출합니다.
- 최신 버전 질문에서 서로 다른 버전이 발견되면 충돌 플래그를 설정합니다.
- 공식 릴리스 목록으로 충돌이 해소되지 않으면 검색 충분성을 낮춥니다.
- 개별 버전 릴리스 페이지를 최신 버전 목록으로 간주하지 않도록 모델 프롬프트에 명시합니다.

버전 추출은 제목·검색 요약의 문자열 패턴에 의존합니다. 페이지 본문에서 버전 목록을 직접 읽거나 버전의 실제 최신성을 증명하지는 않습니다.

### 4. 검색 결과 정렬

관련성 점수에 출처 유형과 게시일 기반 보너스를 더해 정렬합니다. 점수는 검색 결과의 우선순위를 정하기 위한 휴리스틱이며 확률이나 신뢰도 점수가 아닙니다.

### 5. 제한된 재검색

근거 요건을 만족하지 못하면 질문 유형에 맞는 공식 출처 중심 검색어로 최대 한 번 재검색합니다. 재검색 후에도 요건이 충족되지 않으면 답변 생성기에 부족 사유를 전달합니다.

## 테스트

프로젝트 루트에서 실행합니다.

```cmd
python -m unittest discover -s tests -v
```

추가 테스트는 출처 분류, 기업 공식 출처 요건, 공식 릴리스 목록 구분, 버전 충돌 감지, 공식 자료 중심 재검색을 다룹니다.

## 한계 및 후속 작업

- SearXNG가 반환한 제목·요약·URL·게시일 메타데이터에 의존합니다.
- 페이지 본문을 직접 수집하지 않습니다.
- 검색 요약이 부정확하거나 오래되었으면 검증도 실패할 수 있습니다.
- 출처와 답변 문장의 의미적 함의 관계를 검사하지 않습니다.
- 공식 도메인 목록은 지속적으로 보완해야 합니다.
- 다음 단계에서는 페이지 본문 수집, claim extraction, claim-to-source entailment 평가를 별도로 설계해야 합니다.
