# v1.3 — Decision & Evidence Reliability

## Goal

Improve decision consistency between the six agent stages without adding new tools or changing the existing DIRECT / SEARCH / HYBRID architecture.

## Changes

### 1. Current-turn task classification

- Stage 3 classifies only the latest user message.
- Conversation history remains available for reference resolution and answer generation.
- Previous assistant wording no longer contributes keywords to freshness, intent, or tool-candidate heuristics.
- Generic wording such as "알려줘" does not independently imply web retrieval.
- Explicit retrieval requests and freshness markers can still nominate web search.

### 2. Context-aware routing with current-turn safety checks

- The router model still receives the contextualized question so it can resolve pronouns such as "그 버전".
- Deterministic explicit-search and freshness safety rules inspect only the latest user message.
- This prevents an old message mentioning "최신" or "검색" from forcing a later conceptual follow-up into SEARCH.
- If the router model itself fails, the existing conservative SEARCH fallback remains unchanged.

### 3. Evidence-bounded answer generation

- HYBRID prompts more explicitly prohibit industry-wide adoption, production-standard, and preference claims when evidence is insufficient.
- Generic use cases must be described as possible application scenarios, not proof of real deployments.
- The prompt distinguishes company-owned sources from actual customer deployment evidence.

### 4. Deterministic evidence-boundary warnings

The structural validator now receives the search assessment and route. For SEARCH/HYBRID answers it adds visible warnings when:
- the evidence assessment is insufficient;
- a request requires company-official sources but none were found;
- a request requires customer deployment evidence but no customer-case signal was found.

These warnings do **not** prove or disprove individual claims. Semantic entailment verification remains out of scope and is still explicitly reported as not performed.

## Regression coverage

- Follow-up conceptual question should classify as learning, without freshness or web-search requirement.
- Generic "알려줘" wording should not automatically nominate web search.
- Insufficient HYBRID evidence should produce deterministic evidence-boundary warnings.
- Existing six-stage orchestration and context-resolution tests remain in place.

## Validation required

Run locally on the new branch:

```cmd

python main.py
```

Repeat these live cases:
1. `Python 리스트와 튜플의 차이를 설명해 줘.` → DIRECT
2. `그럼 튜플 안에 리스트가 있으면 어떻게 돼?` → DIRECT; no freshness requirement and no web search
3. `현재 Python 최신 안정 버전을 공식 출처로 확인해 줘.` → SEARCH
4. `RAG의 작동 원리를 설명하고 최신 기업 활용 사례를 조사해 줘.` → HYBRID; if customer-case evidence is absent, the answer must say so and include the deterministic warning

## Follow-up fixes from live test (2026-11-09)

The live run found three additional gaps; the branch now includes targeted fixes:

- **Python tuple/list factual guard:** the DIRECT prompt explicitly states that tuples can contain lists, that tuple immutability is not recursive deep immutability, and distinguishes tuple-slot reassignment from mutation of a nested list. This is a prompt-level guard, not a semantic proof checker.
- **Canonical latest release endpoint:** `/downloads/latest` is now recognized as an official release index. Its resolved release-page title can provide the exact patch version even when the search snippet omits the phrase "latest". This addresses the observed 3.15 family-only answer; local search must still confirm that the endpoint result is actually returned.
- **Conservative customer-case signals:** generic phrases such as "적용 사례", "case study", or "구축 사례" no longer independently count as customer deployment evidence. Stronger named-customer/deployed-at signals are required. This reduces false positives but remains heuristic.
- **Incomplete HYBRID retry:** the retry prompt now caps the response at 500 tokens and asks for three short, complete paragraphs rather than a long four-section answer. A length-limited response is still flagged as incomplete; the retry instruction does not guarantee completion.

New regression tests cover the canonical release endpoint, generic company technology articles versus named-customer signals, and the tuple/list prompt facts.
