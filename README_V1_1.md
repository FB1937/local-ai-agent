# Local AI Agent v1.1 — Intelligent Routing

## 1. 이번 버전의 목표

v1.0은 모든 질문에 SearXNG 검색을 수행했습니다. v1.1에서는 Qwen이 질문을 먼저 분류하고, 세 가지 처리 경로 중 하나를 선택합니다.

| 경로 | 동작 | 예시 |
|---|---|---|
| `DIRECT` | 검색 없이 Qwen이 바로 답변 | Python 리스트와 튜플의 차이 |
| `SEARCH` | SearXNG 검색 후 Qwen이 근거 중심 답변 | 오늘 환율, 최신 버전, 최근 뉴스 |
| `HYBRID` | 기본 개념 설명과 최신 검색 자료를 결합 | 데이터 엔지니어 업무 설명 + 현재 채용공고 분석 |

Qwen의 판단을 무조건 신뢰하지 않도록 안전 규칙도 둡니다. 사용자가 웹 검색을 명시하거나 질문이 최신 사실에 의존하는데 Qwen이 `DIRECT`를 선택하면 `SEARCH`로 보정합니다. 분류 요청이 실패하거나 자체 확신도가 설정 기준보다 낮은 경우에도 `SEARCH`로 fallback합니다.

> confidence는 모델이 출력한 자체 확신도이며, 통계적으로 보정된 정확도 확률이 아닙니다. 정확도는 별도의 평가 스크립트로 측정합니다.

## 2. 파일 구성

```text
local-ai-agent/
├── main.py                      # 전체 대화 및 라우팅 흐름
├── router.py                    # 질문 분류 + 안전 규칙
├── llm.py                       # DIRECT / SEARCH / HYBRID별 답변 생성
├── search.py                    # SearXNG 검색
├── evaluate_router.py           # 라우팅 정확도 평가 실행기
├── test_cases/
│   └── routing_cases.json       # 정답 라벨이 포함된 60개 테스트 질문
├── tests/
│   └── test_router_rules.py     # 네트워크 없이 실행하는 안전 규칙 단위 테스트
└── reports/                     # 평가 결과 JSON 저장 위치
```

`run.bat`, `.env`, `.venv`는 기존 프로젝트에 있는 것을 그대로 사용합니다. 이번 v1.1에서 `run.bat`은 수정하지 않습니다.

## 3. 적용 방법

1. 프로젝트 폴더를 백업합니다.
2. 이 패키지의 `main.py`, `llm.py`, `search.py`를 기존 파일에 덮어씁니다.
3. `router.py`, `evaluate_router.py`를 프로젝트 루트에 새로 추가합니다.
4. `test_cases`와 `tests` 폴더를 프로젝트 루트에 복사합니다.
5. `reports` 폴더도 생성하거나 패키지의 빈 폴더를 복사합니다.
6. 기존 `.env`에 있는 다음 값은 유지합니다.

```env
SEARXNG_URL=http://localhost:8080
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=qwen3.5:9b
```

선택적으로 라우터 설정을 추가할 수 있습니다.

```env
ROUTER_CONFIDENCE_THRESHOLD=0.55
ROUTER_TIMEOUT=120
```

현재 기본값을 그대로 쓸 경우 이 두 환경변수는 추가하지 않아도 됩니다.

## 4. 정확도 테스트 준비

테스트 세트는 총 60개이며 경로별로 균형을 맞췄습니다.

| 구분 | DIRECT | SEARCH | HYBRID | 합계 | 용도 |
|---|---:|---:|---:|---:|---|
| 개발 세트 (`dev`) | 5 | 5 | 5 | 15 | 프롬프트와 분류 규칙 조정 |
| 최종 평가 세트 (`holdout`) | 15 | 15 | 15 | 최종 성능 확인 |
| 전체 | 20 | 20 | 20 | 전체 동작 확인 |

각 테스트 케이스에는 질문, 기대 경로, 기대 경로의 근거가 들어 있습니다. 기대 경로는 이번 프로젝트에서 합의한 라우팅 정책에 따른 기준 라벨입니다. 모든 자연어 요청에 하나의 절대적인 정답이 존재하는 것은 아니므로, 애매한 사례는 정책을 먼저 합의한 뒤 라벨을 수정해야 합니다.

### 권장 평가 순서

**1단계: 규칙 단위 테스트**

```powershell
python -m unittest discover -s tests -v
```

이 테스트는 Qwen이나 SearXNG에 연결하지 않고, 명시적 검색 요청·최신 정보·낮은 확신도 등의 안전 규칙이 예상대로 작동하는지 확인합니다.

**2단계: 개발 세트로 튜닝**

```powershell
python evaluate_router.py --split dev
```

Qwen을 15회 호출합니다. 오분류 사례를 확인하고 `router.py`의 시스템 프롬프트나 안전 규칙을 개선합니다. 분류 기준 자체를 변경했다면 테스트 케이스의 기대 라벨도 같은 기준으로 검토해야 합니다.

**3단계: 최종 평가**

분류 프롬프트와 규칙을 확정한 뒤 실행합니다.

```powershell
python evaluate_router.py --split holdout
```

Qwen을 45회 호출합니다. 최종 평가 결과를 확인한 뒤에는 이 holdout 질문을 반복 튜닝에 사용하지 않는 것이 좋습니다. 개선 작업을 계속한다면 새 holdout 질문을 추가합니다.

**4단계: 전체 에이전트 실행**

```powershell
python main.py
```

또는 기존 `run.bat`을 실행합니다. 질문 분석 결과가 `DIRECT`이면 검색을 생략하고, `SEARCH` 또는 `HYBRID`이면 SearXNG를 호출합니다.

## 5. 평가 지표 읽는 법

평가 스크립트는 다음 지표를 표시합니다.

- **모델 원판정 정확도:** 안전 규칙을 적용하기 전 Qwen이 직접 출력한 경로의 정확도
- **안전 규칙 적용 후 정확도:** 프로그램이 실제로 사용하는 최종 경로의 정확도
- **Precision:** 특정 경로라고 예측한 것 중 실제로 해당 경로인 비율
- **Recall:** 실제로 해당 경로여야 하는 질문 중 찾아낸 비율
- **F1:** Precision과 Recall의 조화평균
- **Macro F1:** 세 경로의 F1을 동일한 비중으로 평균한 값
- **혼동 행렬:** 어떤 경로를 어떤 경로로 잘못 분류했는지 보여 주는 표

예를 들어 `HYBRID → SEARCH` 오분류가 많다면 혼합 요청의 기준이 너무 좁거나, 라우터 프롬프트가 기본 개념 설명과 최신 정보 조사를 함께 처리해야 한다는 점을 놓치는지 살펴봅니다.

각 실행의 상세 결과는 `reports/routing_eval_<split>_<timestamp>.json`에 저장됩니다. 모델 원판정, 최종 경로, 확신도, 검색어, 판단 이유, 소요 시간, 오분류 사례를 확인할 수 있습니다.

## 6. 테스트의 한계와 합격 기준 제안

- 현재 45개 holdout은 초기 개발 검증용 소규모 세트이지, 실제 사용자 전체 질문을 대표하는 통계 표본은 아닙니다.
- 분류 정확도는 답변의 사실성이나 검색 결과의 품질을 측정하지 않습니다. 이는 추후 별도 평가가 필요합니다.
- `HYBRID`는 기본 설명과 최신 자료가 모두 필요한 요청으로 정의했습니다. 경계 사례는 평가 전에 기준을 명확히 해야 합니다.
- 첫 목표는 holdout 정확도 85% 이상과 세 경로 모두에서 균형 잡힌 Recall을 달성하는 것입니다. 단, 이 수치는 초기 개발 목표이지 업계 표준은 아닙니다.
- 실제로 중요한 것은 전체 정확도만이 아닙니다. 최신 정보가 필요한 질문을 `DIRECT`로 잘못 보내는 오류를 특히 주의해야 합니다.

## 7. API 응답 구조

`router.py`는 Ollama `/api/chat`의 `format`에 JSON Schema를 전달해 다음 구조의 응답을 요청합니다.

```json
{
  "route": "SEARCH",
  "reason": "현재 채용공고 확인이 필요함",
  "search_query": "2026 국내 신입 데이터 엔지니어 채용공고",
  "confidence": 0.91
}
```

Ollama의 `/api/chat`은 `format` 필드에 JSON 모드 또는 JSON Schema를 지정할 수 있습니다. 실제 반환 내용은 코드에서 JSON 파싱과 필수 경로 검증을 다시 수행합니다.

## 8. 알려진 범위

- v1.1은 질문 라우팅만 구현합니다. 도구 선택·연쇄 실행을 자율적으로 계획하는 v2.0 에이전트는 아닙니다.
- SearXNG 검색 결과의 중복 제거·관련성 점수화·출처 교차 검증은 v1.2~v1.3 범위로 남겨 둡니다.
- 대화 기록과 장기 기억은 v1.4~v1.5 범위로 남겨 둡니다.
